# 0.3.6

상태: Claude 자동 저장 구현 브랜치. PR 검토 전이며 main에 배포하지 않는다.

## PR #9 분석

참고: https://github.com/hongdangmoo49/oh-my-obsidian/pull/9

PR #9는 SessionEnd에 새 `claude -p` 호출을 등록했다. 원래 세션 ID나 문맥을
새 프로세스에 전달하지 않아 현재 작업 요약을 보장할 수 없으며, 종료 시
재호출과 시간 제한도 고려해야 한다. 설정 JSON 파싱 오류를 무시하고 빈 설정을
쓰는 코드는 기존 권한 및 다른 hook을 잃게 할 수 있다.

따라서 자동 저장 부분은 교체하고, 과거 기록 복원 명령과 transcript-summarizer
에이전트는 유지한다. 현재 대화의 모델이 응답 전에 요약을 만드는 방식으로
Codex와 동일한 저장·복구·검사·완료 확인 엔진을 재사용한다. 원문 transcript를
자동 저장 경로에서 읽거나 새 Claude 프로세스를 시작하지 않는다.

## 적용 방식

- 플러그인 기본 hook: SessionStart, UserPromptSubmit, Stop.
- Claude의 prompt_id를 응답 ID로 사용한다. 없는 버전은 원문 저장 없이 UUID
  marker를 만들어 해당 세션의 Stop에서 확인한다.
- Claude 세션 ID는 별도 namespace를 사용하여 Codex 노트와 섞지 않는다.
- 작업 요약·결정·다음 할 일을 같은 노트에 추가하고 Git commit/push는 하지 않는다.
- 성공은 조용히 종료하며 미확인은 짧은 경고만 출력한다. 강제 저장이나
  갑작스러운 터미널 종료 후 복구를 보장하는 것은 아니다.

기존 사용자는 업데이트 후 `/oh-my-obsidian:enable-auto-save`를 실행한다.
plan/apply 도우미가 PR #9의 정확한 기존 SessionEnd 명령만 제거하고 다른
hook과 설정은 보존한다. 수정 전 설정을 백업하며 invalid JSON은 덮어쓰지 않는다.
setup-state가 없는 예전 볼트는 별도 승인 후 metadata-only attachment를 수행한다.
기존 Markdown은 변경하지 않는다. 플러그인을 다시 로드하거나 새 세션을 시작한다.

등록된 자동 저장 정책은 `.claude/oh-my-obsidian.local.json`에서 관리한다.
`--disable` plan/apply로 다른 플러그인에 영향을 주지 않고 자동 저장만 끌 수 있다.

Codex의 기존 검증과 저장 규약은 유지한다. 민감정보 검사는 휴리스틱이며
완료 기록은 저장 일관성을 확인할 뿐 모델 요약의 정확성을 보장하지 않는다.

## 검증 현황

- 전체 테스트: 82개 통과, 플랫폼 관련 9개 건너뜀, 실패 0개.
- Claude 최신 prompt_id와 구버전 UUID fallback, 실제 파일 저장과 완료 확인,
  이전 결정·할 일 보존, 비활성화, 설정 손상 및 metadata junction을 검증했다.
- Codex 실제 새 세션 스모크와 기존 적대적 검증은 통과했다.
- 설치된 Claude CLI 2.1.156의 실제 새 세션은 현재 API 연결에서
  `401 Authentication Failed`로 실패했다. 인증 상태 표시는 로그인됨이지만
  실제 API 요청은 거부됐다. 계정/인증 설정은 임의로 변경하지 않았다.
- 실제 Claude 모델 응답에 의한 자동 저장 E2E 확인은 인증 복구 후 재실행이 필요하다.

```text
node qa/scripts/claude-session-smoke.mjs <claude-binary>
```

위 검증이 완료되기 전에는 PR을 배포 완료로 처리하지 않는다. main에 직접
push하거나 현재 사용자의 이전 Claude 설치/설정을 강제로 바꾸지 않는다.
