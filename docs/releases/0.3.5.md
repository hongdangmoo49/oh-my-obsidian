# 0.3.5

상태: 로컬 릴리스 준비. 원격 푸시 및 마켓플레이스 배포는 하지 않았다.

## 변경 사항

- Codex hook 설치에 조용한 자동 저장 지침과 응답별 완료 확인을 포함한다.
- 같은 세션 노트에 작업 요약, 결정, 다음 할 일을 추가하며 이전 기록을 보존한다.
- 사용자 편집, 오래된 리비전, 동시 갱신 및 볼트 밖 경로를 거부한다.
- 자동 저장 비활성화 설정을 환경변수와 함께 사용해도 유지한다.
- 검증된 백업과 저널로 상태 손상 및 저장 중단을 복구한다.
- 완료 기록과 실제 노트 해시를 확인한다. 성공은 조용히 종료하고 미확인은 차단 없이 경고한다.
- 패턴 기반 민감정보 검사를 자동 저장에 적용하고 의심 입력은 값 노출 없이 거부한다.
- 테스트 환경을 실제 계정의 HOME, 작업 디렉터리 및 볼트 설정에서 격리한다.

## 적용 방법

플러그인 업데이트만으로 기존 프로젝트에 복사된 hook 실행 파일은 갱신되지 않는다.
업데이트된 플러그인의 설치 도우미를 사용해 기존 프로젝트에 다시 적용한다.

```text
node scripts/codex-hooks.mjs plan --repo-root <project> --vault <vault>
node scripts/codex-hooks.mjs apply --repo-root <project> --vault <vault>
```

새 세션에서 프로젝트 hook 설정을 검토하고 허용한다. 자동 저장은 승인된
볼트 연결과 hook 적용 이후에 동작하며, Git commit 또는 push는 실행하지 않는다.

## 제한 사항

- 조용한 저장은 모델 지침 기반이며 강제 저장을 보장하지 않는다.
- 완료 기록은 디스크 일관성을 검증하며 요약 내용의 정확성을 보장하지 않는다.
- 응답별 완료 확인에는 런타임의 `turn_id`가 필요하다.
- 민감정보 검사는 휴리스틱이며 오탐 및 미탐이 가능하다. 자동 노트는 64 KiB로 제한된다.
- 수동 저장은 자동 저장 검사와 별개다. 기존 위험 노트는 명시적 검토가 필요하다.
- 다른 PC, 살아 있는 프로세스, 소유자 불명의 잠금은 자동 해제하지 않는다.

## 배포 순서

### 검증 현황

- Windows 전체 테스트: 76개 통과, 플랫폼 관련 9개 건너뜀, 실패 0개.
- 적대적 검증: 경로 탈출, 기록 소실, 비활성화 무시, 상태 손상, 완료 미확인,
  가짜 비밀값 저장에 대한 검증을 통과했다.
- 실제 Codex CLI 0.160.0과 `gpt-6.1-sol`에서 새 세션 스모크를 2회 통과했다.
  워크스페이스 권한 프로필과 Windows `unelevated` sandbox를 명시한 실행이다.
  테스트 파일 생성, 세션 노트 1개, 응답 완료 receipt 및 실제 노트 해시를 확인했다.
- 초기 검증 스크립트의 프로젝트 신뢰 override 전달 오류를 수정하고
  `--strict-config`로 설정 검사를 강제했다. Windows sandbox 선택도 명시한다.
- Windows `elevated` 모드와 다른 플랫폼의 실제 CLI 스모크는 별도 검증이 필요하다.
- hook 정의를 검토한 자동화 호출에만 trust bypass를 적용했다. 실제 사용자
  설정이나 관리자 권한 정책은 변경하지 않았다.

실제 CLI 검증은 사용자 인증이 설정된 환경에서 다음과 같이 실행한다. 이
스크립트는 작업 저장소 하위의 `.omob-live-smoke-*` 임시 저장소와 임시 볼트만
사용하며 종료 시 정리한다. 모델을 지정하지 않으면 CLI 기본 모델을 사용한다.
Windows sandbox 기본값은 `elevated`이며, 이미 설정된 sandbox 환경에서 실행한다.
`unelevated`는 공식 fallback이며 더 약한 격리임을 알고 명시적으로 선택한다.

```text
node qa/scripts/codex-session-smoke.mjs <native-codex-binary> [model] [elevated|unelevated]
```

쓰기 가능한 정상 세션에서 위 검증이 통과하기 전에는 배포 완료로 처리하지 않는다.

1. 전체 테스트 및 적대적 검증을 실행한다.
2. 임시 저장소와 임시 볼트에서 실제 Codex 새 세션을 검증한다.
3. 릴리스 커밋을 원격 main에 반영한다.
4. 마켓플레이스를 갱신하고 사용자 업데이트에서 버전을 확인한다.

로컬 버전 변경과 커밋만으로 원격 마켓플레이스에 배포된 것은 아니다.
